Pymablock · a conceptual guide

From source operators to an effective operator algebra

We want to express an effective Hamiltonian using fewer operators than the original model. This branch lets us specify retained generators and their relation to the source modes, then performs the perturbative calculation in that retained operator algebra. It also keeps the information about source processes that cannot be expressed within the retained algebra on their own.

We will begin with the operator bases used to write a two-mode model and its one-mode effective description. The state-space embedding will enter afterward, as the mathematical explanation for how operators are translated and why their products need special care.

1. Choose the operators of the effective model

Consider two fermionic modes with annihilation operators s and v. Their number operators are ns = s†s and nv = v†v, where a dagger denotes the adjoint. An uncoupled energy and a hopping perturbation give the Hamiltonian

H = H₀ + V,
H₀ = εs ns + εv nv,
V = g(v†s + s†v).

The source Hamiltonian is an expression in these generators and their products. For a single fermion, a basis for operators is {I, s, s†, ns}: any operator on that mode can be written as a linear combination of these four elements. For two modes, we use ordered products of the corresponding elements for both modes, keeping track of fermionic signs. This is an operator basis; its elements act on states.

Suppose we want the effective Hamiltonian to use just one fermion, which we call t. Its operator basis is {I, t, t†, nt}. The desired output is therefore a combination of operators from this smaller algebra. In our example it will be proportional to nt, with an energy coefficient that includes the effect of coupling to mode v.

Choosing t alone does not say which part of the source model it describes. We must also specify its relation to the source modes and the occupation of the mode we eliminate. That is the information provided by the embedding descriptor.

2. Specify the relation between the two operator descriptions

embedding = Embedding(
    target=(target,), occupations={source: N(target), virtual: 0}
)

Here N is NumberOperator, and source, virtual, and target stand for s, v, and t. The target tuple explicitly declares the retained fermionic generator. The occupation dictionary says that the source number follows its number operator, while the virtual mode has reference occupation zero. The backend uses this descriptor to translate source operator terms into the target algebra. We will call this translation R.

R(s) = t,   R(s†) = t†,   R(ns) = nt,
R(v) = R(v†) = R(nv) = 0,   R(I) = I.

These relations describe the simple two-mode embedding above. They tell us, for example, that the directly translated unperturbed Hamiltonian is εsnt. They do not mean that we can replace each source generator independently inside every product. Setting the reference occupation of v to zero still allows that mode to be created and then annihilated in a composite operation.

The fermionic identity vv† = I − nv makes the distinction explicit:

R(vv†) = I,   but   R(v)R(v†) = 0.

Creating a particle in an empty virtual mode and then removing it returns to the original occupation. Translating each factor separately discards that process. Thus the source-to-target translation acts on whole operator terms and is linear, but it does not generally preserve multiplication.

The implementation calculates with operator bases, but the source-to-target map is a compression, rather than an invertible change of operator basis or a multiplication-preserving substitution. The treatment of products is the essential extra ingredient.

3. Why a state-space embedding defines these operator rules

To understand the translation precisely, we can ask what the retained fermion means on states. Each fermionic mode can be empty or occupied. In source notation, |1, 0⟩ means that s is occupied and v is empty. The descriptor above gives the following state map W:

W |0⟩ = |0, 0⟩,     W |1⟩ = |1, 0⟩.

The two states on the left are the states on which the target operators act. The map embeds them as source states with the virtual mode empty. It preserves inner products, so W†W = I. We can now define the translation of any source operator X:

R(X) = W†XW.

Reading right to left, we express a target state in the source model, apply X, and return its retained component to target coordinates. This gives the operator relations in section 2. The implementation computes this compression using occupation rules and operator terms; it generally does not construct the matrix W.

Conversely, a target operator A has the source-space representative WAW†, which acts as zero outside the embedded subspace. This is a literal embedding of target operators into source operators supported on that subspace. The backend’s compression R runs in the other direction. Distinguishing these directions helps explain why compression can discard information.

We name the projectors onto the reference subspace and everything outside it:

P = WW†,     Q = I − P.

In our example, P keeps the states with the virtual mode empty, while Q keeps those with it occupied. These state-space objects explain the algebraic rules. They do not require the implementation to enumerate a basis for the complementary space.

4. Recover the operator contribution that direct compression misses

Applying R to the hopping perturbation gives zero. A single hop changes the virtual occupation, so it has no action entirely within the reference subspace. Nevertheless, two hops can contribute an operator in the target algebra:

R(V) = 0,     R(V²) = g²nt.

The second relation records the amplitude for leaving the reference subspace and returning. It is not yet an energy correction: perturbation theory must also account for the energy of the intermediate state. We take g real and small compared with the separation of the two unperturbed energies.

The following diagram separates the embedding from the two hopping operations. The arrows show a path contributing to perturbation theory, rather than a literal time sequence of measured particle positions.

The embedding fixes the reference subspace

The retained occupied state becomes |1, 0⟩ in the source space. “Virtual mode empty” specifies the retained states; it does not remove that mode from the Hamiltonian.

The two hops each contribute an amplitude g. Second-order perturbation theory weights this path by the inverse energy difference between its starting state and its intermediate state:

δE = g² / (εs − εv).

The empty state has no particle to hop, so its correction is zero. An operator that gives δE on the occupied retained state and zero on the empty one is δE ntarget. Thus, through second order, the effective Hamiltonian is

Heff = εs ntarget + [g² / (εs − εv)] ntarget + higher orders.

If the virtual mode is higher in energy, the denominator is negative and this shift lowers the retained occupied level. The formula requires distinct unperturbed energies; near degeneracy, choosing both modes as retained degrees of freedom is the appropriate starting point.

Fixing an occupation in the embedding specifies the reference subspace. It does not prohibit the Hamiltonian from changing that occupation during a virtual transition. Keeping those transitions is what distinguishes the effective Hamiltonian from direct compression.

5. Keep the missing products as pairs of operators

The example suggests what information is needed: which operator takes a retained state outside, and how another operator brings it back. We can keep that information as an expression involving operators, rather than as a vector with one entry for every complement state.

Suppose a source-space operator X acts on an embedded state. The part of its output outside the retained space is described by the map

C = QXW.

Reading right to left, W embeds, X acts, and Q removes any component still inside the retained subspace. For the hopping example, X = V. The map knows how to produce the outside component for any retained input state.

At higher perturbative orders, a retained-space operator may act before the excursion. Calling that operator A, the expression becomes QXWA. The class OperatorMap represents sums of these expressions by storing pairs (X, A). The embedding and the projector are shared context, so each term only needs its source operator and its retained operator.

The crucial operation is to combine an outgoing map with a returning one. Take C = QXW and D = QYW. Their product C†D starts in the retained space, passes through the complement, and ends in the retained space. Using Q² = Q and then substituting Q = I − WW†, we obtain

C†D = W†X†QYW
= W†X†YW − (W†X†W)(W†YW).

In the operator notation introduced earlier, this is R(X†Y) − R(X†)R(Y): precisely the part lost by translating the factors separately. Every expression on the last line is a compression to the retained space. The first term permits all intermediate states. The second removes the paths whose intermediate state was retained. Their difference therefore counts only the excursions through the complement.

For our hopping example, both single-hop compressions vanish, but the two-hop compression does not. This identity explains how the code preserves the second-order process even though there is no stored matrix for the complement.

Longer paths also involve operations within the complement, such as QHQ. The implementation stores these as operations waiting to be applied to an outgoing map. The internal class ModuleEndomorphism holds source actions, sums, and products for this purpose. It uses the same projector identities when those actions are evaluated.

6. Translate operator terms through their occupation changes

The map algebra above reduces the problem to two practical tasks: calculate compressions such as W†XW, and determine the energy difference for an excursion. Both tasks use the way an operator changes occupations.

The branch represents source operators using NumberOrderedForm. It stores the operator terms that occur, rather than constructing a complete operator-basis transformation matrix. Conceptually, each term describes creation and annihilation operations together with a coefficient that can depend on occupations. A transition view then asks: given some starting occupations, which occupations result, and with what amplitude?

For example, v†s changes (1, 0) into (0, 1). For a boson, annihilating a particle in occupation state n also contributes the factor √n. For fermions, moving creation and annihilation operators past other occupied modes can contribute minus signs. The transition calculation carries these weights along with the occupation changes.

To compress an operator, the backend applies those transitions to occupations described by the embedding and determines which outputs can be expressed as retained states. On the symbolic route it translates the occupation changes into target operators. On the finite matrix route it applies them to the enumerated retained states and fills the corresponding matrix entries. Neither route enumerates a basis for the complement.

The supported unperturbed Hamiltonian H₀ is diagonal in source occupations. Consequently, the code can obtain an intermediate state’s energy by substituting its occupations into the expression for H₀. The linear equation used in block diagonalization—the Sylvester equation—then reduces channel by channel to division by an energy difference. This is the implementation counterpart of the denominator εs − εv in our example.

7. Choose the target operator representation

The direct fermion mapping used above retains whole fermionic degrees of freedom. Each source mode either follows one distinct target fermion or has a fixed occupation of zero or one. The code also tracks the signs associated with fixed occupied modes, so the target fermions retain their operator algebra.

Sometimes the retained states are better described by a shared occupation label. For example, suppose we want exactly one particle across two modes. We declare a target spin lowering operator s and use its number operator N(s) = s†s to specify both source occupations. Its number eigenvalue, which we call q, is zero or one:

s = SigmaMinus("s")
embedding = Embedding(
    target=(s,), occupations={a: N(s), b: 1 - N(s)}
)

For q = 0, the encoded state is |0, 1⟩; for q = 1, it is |1, 0⟩. Using the same coordinate in both expressions imposes the correlation between their occupations. The target algebra is the spin algebra explicitly declared by SigmaMinus("s"). The backend derives the binary occupation coordinate from that declaration.

For a spin larger than one half, the target declaration also supplies its dimension. For example, target={JminusOp("S"): 3} declares a spin-1 representation. Its number-like coordinate is JzOp("S") + 1, with values zero, one, and two in units where ℏ = 1. Mapping a source boson occupation to that expression retains its first three levels.

Binary spin and fermion targets return symbolic NumberOrderedForm expressions in the declared generators. A target containing a higher spin returns a finite matrix, with basis states ordered by increasing magnetic quantum number. The full source space and its complement remain unenumerated.

8. Where the embedding fits into Pymablock

Pymablock already has a perturbative recurrence that constructs a transformation separating blocks of a Hamiltonian. This branch supplies that recurrence with a two-block problem: the retained space and its complement. The recurrence can add, multiply, and take adjoints of its blocks even though they are represented by different kinds of objects.

Action of the blockWhat the branch stores
Within the retained spaceThe compressed operator W†HW, as a target operator expression or finite matrix.
From retained states to the complementAn OperatorMap representing QHW.
From the complement back to retained statesThe adjoint of an outgoing map, for the supported Hermitian problem.
Within the complementA deferred operator action representing QHQ.

A multiplication dispatcher applies the appropriate algebra for each pair of block types. In particular, multiplying a returning map by an outgoing map uses the subtraction identity from section 5. The existing recurrence therefore incorporates virtual paths without needing their full-space matrix representation.

At the public API, the embedding is supplied where subspace eigenvectors would otherwise be passed:

embedding = Embedding(
    target=(target,), occupations={source: N(target), virtual: 0}
)
H_eff, U, U_dagger = block_diagonalize(
    [H0, V], subspace_eigenvectors=embedding,
)
second_order = H_eff[0, 0, 2]

The returned objects are perturbation series evaluated on demand. In the last line, the first two indices select the retained-to-retained block, and the final index requests its second-order coefficient. For our example, that coefficient is g² ntarget / (εs − εv), the expression checked by the branch’s public API test.

The main saving comes from keeping occupations and operator actions symbolic wherever this representation is supported. The calculation still has to manage the growth of perturbative expressions, and an explicit retained matrix still grows with the retained dimension. What it avoids is constructing all the states outside the retained model just to account for their influence.

9. The tunable coupler and ring-exchange examples

Both examples use Embedding with explicitly declared target spins, even though the source generators are bosonic in one example and fermionic in the other. The occupation rule determines what a target spin means in the source model.

The tunable coupler: three oscillators become two spins

The source model contains two computational modes, a₁ and a₂, and a coupler mode, ac. All three are nonlinear bosonic oscillators: each has an occupation-dependent energy and, in principle, arbitrarily many levels. The example couples each pair through terms of the form gij(aᵢ† − aᵢ)(aⱼ† − aⱼ), including direct coupling between the computational modes.

We want a two-qubit effective Hamiltonian. The following descriptor retains occupations zero and one of each computational oscillator and fixes the reference coupler occupation to zero:

from sympy.physics.quantum.boson import BosonOp
from sympy.physics.quantum.pauli import SigmaMinus
from pymablock.number_ordered_form import NumberOperator as N
from pymablock.second_quantization import Embedding

a1, a2, ac = (BosonOp(name) for name in ("a1", "a2", "ac"))
b1, b2 = SigmaMinus("b1"), SigmaMinus("b2")
embedding = Embedding(
    target=(b1, b2), occupations={a1: N(b1), a2: N(b2), ac: 0}
)

The target operators b₁ and b₂ are spin lowering operators, with bᵢ|1⟩ = |0⟩. Their number eigenvalues q₁ and q₂ specify the source occupations. This gives a target operator basis made from products of {I, bᵢ, bᵢ†, bᵢ†bᵢ}. Equivalently, the effective Hamiltonian can be expressed in two-qubit Pauli operators.

R(a₁) = b₁,   R(a₂) = b₂,   R(ac) = 0,
R(n₁) = b₁†b₁,   R(n₂) = b₂†b₂,   R(nc) = 0.

The state interpretation of exactly the same rule is W|q₁, q₂⟩ = |q₁, q₂, 0⟩. Thus the target algebra acts on four retained states. The coupler has no target generator because its occupation is fixed in all four.

This does not truncate every source operator to a two-level operator before the calculation. For example, creating and then annihilating a boson in computational mode i gives

R(aᵢaᵢ†) = I + bᵢ†bᵢ,
R(aᵢ)R(aᵢ†) = bᵢbᵢ† = I − bᵢ†bᵢ.

On the occupied qubit state, the first expression gives two: the source oscillator can go from occupation one to two and back, with two factors of √2. Multiplying the target operators gives zero, because a target spin cannot be raised beyond occupation one. The difference is precisely a virtual process that must be preserved.

Virtual paths can also populate the coupler, for example |1, 0, 0⟩ → |0, 0, 1⟩ → |0, 1, 0⟩. Such a path contributes to an exchange operator b₂†b₁; its reverse contributes the adjoint. Higher-order paths also generate occupation-dependent energy shifts, expressible through number operators or Pauli Z products. The coupler frequency and the oscillator anharmonicities enter through the intermediate energies. Tuning these parameters changes effective coefficients while leaving the embedding rule unchanged.

The branch’s public-API acceptance test builds this embedding and requests the fourth-order retained Hamiltonian. An analytic check verifies the mediated exchange, and the fourth-order result is checked for Hermiticity.

Ring exchange: eight fermionic modes become four spins

The ring example is a four-site Hubbard square. Every site has an up and a down fermionic mode, so the source operator algebra has eight annihilation generators. The unperturbed energy is H₀ = U ∑ᵢ nᵢ↑nᵢ↓, which charges energy U for a doubly occupied site. The perturbation hops fermions between neighboring sites around the square with amplitude −t.

We want an effective spin model with exactly one fermion on each site. One binary coordinate per site is enough: value one means up occupied, while value zero means down occupied. The two source occupations therefore share a coordinate:

from sympy.physics.quantum.fermion import FermionOp

up = [FermionOp(f"c{i}_up") for i in range(4)]
down = [FermionOp(f"c{i}_down") for i in range(4)]
spins = tuple(SigmaMinus(f"s{i}") for i in range(4))
embedding = Embedding(
    target=spins,
    occupations=(
        {up[i]: N(spins[i]) for i in range(4)}
        | {down[i]: 1 - N(spins[i]) for i in range(4)}
    ),
)

At each site this enforces nᵢ↑ + nᵢ↓ = 1. It excludes both empty and doubly occupied sites from the reference subspace. Four independent binary coordinates give sixteen retained spin configurations. This is stronger than fixing the total particle number to four: total number alone would also permit configurations containing a hole and a doubly occupied site.

Let bᵢ lower the target coordinate from one to zero, and write Nᵢ = bᵢ†bᵢ. The occupation operators translate as

R(nᵢ↑) = Nᵢ,   R(nᵢ↓) = I − Nᵢ,   R(nᵢ↑nᵢ↓) = 0.

The output algebra is generated by these four spins. An individual source fermion creation or annihilation operator compresses to zero because it violates single occupancy. Composite fermionic operations can nevertheless become nonzero spin operators. The backend obtains their coefficients, including fermionic signs, from the source operator ordering and the occupation map.

A single allowed hop creates an empty site and a doubly occupied site. It therefore leaves the reference subspace, even though it preserves total particle number. A second hop can restore single occupancy and exchange neighboring spins. Four hops around the square can restore all occupations while cyclically permuting the spins, producing ring exchange.

A particularly transparent target matrix element connects the alternating configurations |1, 0, 1, 0⟩ and |0, 1, 0, 1⟩. In target operators, the corresponding four-spin flip and its reverse appear as

Heff(4) ⊃ (40t⁴/U³)
× (b₀b₁†b₂b₃† + b₀†b₁b₂†b₃).

The public-API test checks the coefficient 40t⁴/U³ of the number-ordered term with powers (1, -1, 1, -1). Here positive powers denote lowering and negative powers raising. This is one contribution within the full fourth-order Hamiltonian, not an expression for all its terms.

The example also reports the cyclic-permutation convention K(C₄ + C₄†), where C₄ moves the four spins by one site around the square. On an alternating configuration, both cyclic directions lead to the same final configuration. Its matrix element is therefore 2K, giving K = 20t⁴/U³ for this benchmark.

In both models, the embedding fixes the interpretation of the target operators. The perturbative calculation determines their coefficients by retaining source operator products that temporarily violate the reference occupation constraints. That is how a bosonic coupler or fermionic charge fluctuations can disappear from the final generators while remaining present in the effective interactions.

10. Spin-1, superpositions, and explicit isometries

The synthetic spin-1 example does use superpositions. Its source model contains a cavity, a Floquet ladder, and a two-level ancilla. Before defining the embedding, the model rotates the ancilla basis by a matrix that depends on cavity occupation. The selected dressed ancilla state at occupation n is

|+ₙ⟩ = [eiφₙ/2|g⟩ + e−iφₙ/2|e⟩] / √2.

Thus, before that dressed-basis rotation, the target state with cavity occupation n corresponds to a superposition of bare ancilla states. The example applies the rotation to the Hamiltonian itself. In the resulting source coordinates, the selected dressed branch has occupation zero, and the embedding is simple:

from sympy.physics.quantum.spin import JminusOp, JzOp

embedding = Embedding(
    target={JminusOp("S"): 3},
    occupations={
        cavity: JzOp("S") + 1,
        floquet: 0,
        dressed_ancilla: 0,
    },
)

The spin magnetic quantum numbers −1, 0, 1 correspond to cavity occupations 0, 1, 2. The effective operator is a 3 × 3 matrix in that order. Declaring a spin target does not force the Hamiltonian to be a single spin generator; the drive phases determine its matrix elements.

An explicit isometry means writing the embedding as actual orthonormal columns. Column j is the source-space vector assigned to target basis state j. For example, two orthogonal superpositions can be specified by

W = (1/√2) [[1, 0], [1, 0], [0, 1], [0, 1]],
W†W = I₂.

This notation lists the rows of a 4 × 2 matrix: its first column is (1, 1, 0, 0)ᵀ/√2, and its second is (0, 0, 1, 1)ᵀ/√2. It maps two target states to superpositions in a four-dimensional source basis. For a source Hamiltonian represented in that basis, Pymablock accepts such columns through subspace_eigenvectors=(W,).

The structured constructor avoids writing these columns by using occupation rules. It does not itself construct superpositions or rotate the Hamiltonian. In the spin-1 example, the occupation-dependent rotation supplies that missing step before the structured embedding is applied. The public API test checks the first-order spin-1 matrix and compares its second-order correction with a direct finite occupation-matrix calculation.

Scope of the current implementation

The explanation above describes the package implementation on this branch. Its structured embedding route currently accepts an unseparated Hermitian Hamiltonian with H₀ diagonal in source occupations. The constructor requires integer affine occupation rules with full column rank and validates the physical source occupation ranges. Fermion targets currently require direct one-to-one source fermion assignments, and mixed spin/fermion targets are rejected. Arbitrary superpositions of source basis states are outside these structured descriptors.

Additional API and representation limits

The route chooses its own Sylvester solver and does not accept custom solver options or fully_diagonalize. A zero energy denominator raises an error unless the implementation finds that the corresponding channel vanishes after projection.

There is no number= option: a total-number filter cannot simply be attached to a full fermionic generator algebra. Single occupancy in the ring example is expressed explicitly through the occupation rules.

General nonlinear occupation rules are rejected. The symbolic transition route requires a constant target shift, so the constructor accepts only the affine family that this backend can validate. Higher-spin targets use finite target matrices.
